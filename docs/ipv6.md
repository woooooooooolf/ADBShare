# IPv6 与共享协议模式

V0.11.0 起支持 IPv6 共享入口及每组独立的协议模式，兼容原有 IPv4 配置。

## 配置共享组

1. 选择网卡，查看其 IPv4 / IPv6 地址可用状态。
2. 选择“仅 IPv4”“仅 IPv6”或“IPv4 + IPv6”。双协议必须选择同一网卡上的一个 IPv4 和一个 IPv6 地址，两者使用相同端口。
3. 为每种监听协议至少填写一个来源地址或网段。IPv4 支持 `/0–32`，IPv6 支持 `/0–128`；单地址分别等同于 `/32`、`/128`。不接受 IPv4 映射 IPv6 地址。
4. 保存并共享。没有所需协议的可用地址时，保存 / 启动按钮不可用；请恢复网络或选择可用的单协议模式。

例如，IPv6 地址 `fd12:3456:789a::10`、共享端口 `15037`：

```powershell
adb -H "[fd12:3456:789a::10]" -P 15037 devices -l
adb -H "[fd12:3456:789a::10]" -P 15037 -s SERIAL shell
```

IPv6 的 `-H` 参数保留方括号。远端访问区会生成当前配置对应的命令；双协议提供两套命令。

## 网卡与协议检查

- 网卡列表来自系统实际分配的地址，按网卡身份分组。仅有一种协议地址的网卡仍可使用对应单协议模式。
- 界面定期重新枚举地址并检查绑定能力。系统没有返回任何地址的网卡不会作为新网卡选项显示；原配置指向已消失的网卡或地址时显示不可用，不自动改选其他网卡。
- Windows 使用系统报告的 Preferred 单播地址，排除尚在重复地址检测、重复或弃用的地址。Linux 另外读取 IPv6 地址状态，排除 tentative、DAD-failed 和 deprecated 地址。
- 同时检查网卡运行状态，并以相应地址族创建套接字、尝试绑定本地地址。失败时不可用，界面会显示地址对应的原因。
- “无可用地址或协议未启用”表示当前没有可供共享的该协议地址，不把“未分配地址”直接断言成“协议栈已禁用”。程序不自动启用协议栈或重新配置网卡。
- 启动时再次检查当前网卡与地址，并预留所有监听端口；任一失败会释放预留，不创建部分运行的双协议组。Windows 在预留成功后才请求应用防火墙规则，并在实际开始监听前再次检查网卡与地址，避免等待提权时地址已失效。
- 运行期间地址失效会反映在界面。程序不自动切换地址、网卡或协议；仍可停止组，恢复后重新选择并启动。

检查只证明本机地址当前可以绑定，不证明其他电脑可路由到该地址，也不证明系统防火墙、路由器或交换机已允许访问。

## 链路本地地址

`fe80::/10` 仅限相同链路。监听端根据当前选定网卡获取 scope id；客户端必须使用**远端电脑自己的出站接口编号**，两端编号通常不同。

```powershell
# 将 INTERFACE 替换为远端电脑的实际接口编号
adb -H "[fe80::1234%INTERFACE]" -P 15037 devices -l
```

Windows 可在远端使用 `Get-NetIPInterface -AddressFamily IPv6` 查看接口编号；Linux 可用 `ip -o link` 查看。优先选择稳定的 ULA 或全局单播地址；临时 IPv6 地址可能变化，地址变化后需重新选择共享地址。全局单播地址即使用于同一局域网，也会触发非局域网来源警告。

## 来源与防火墙

`0.0.0.0/0` 只允许所有 IPv4 来源；`::/0` 只允许所有 IPv6 来源。双协议的来源分别匹配，不跨地址族放行。回环接入继续按本机连接处理，隧道入口需自行限制访问。

Windows 为两种协议分别建立规则，每条规则限定本地监听地址、TCP 端口及对应协议的来源范围。停止保留规则，删组 / 退出清理新旧规则。Linux 继续由用户管理系统防火墙。

## 兼容边界

- 仅 IPv6 指共享入口仅监听 IPv6；本机上游 ADB Server 仍通过 `127.0.0.1` 连接，因此不承诺整个系统禁用 IPv4 后运行。
- 每组继续使用一个具体网卡的具体地址，不新增所有网卡通配监听。
- 配置兼容原有 IPv4 组。新 IPv6 配置无法由旧程序读取，降级前应保存原配置备份。
- ADB 命令支持范围不因地址族改变，`forward` / `reverse` 仍不支持。
- 自动化使用虚拟设备；双机 IPv6 LAN、真实 Android 设备和实际防火墙规则生效仍需实机验收。具体记录见 [验证说明](validation.md)。
