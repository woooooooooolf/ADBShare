# 仓库维护

ADBShare 在 V0.9.0 发布后改为公开仓库。源码、历史提交和正式 Release 对外可见；后续维护遵守以下约定。

## 功能与协作

| 项目                                  | 设置                                     |
| ------------------------------------- | ---------------------------------------- |
| 默认分支                              | `main`                                   |
| 首页链接                              | 最新 Release                             |
| Issues                                | 开启，用于问题反馈与功能讨论             |
| Wiki / Projects / Discussions / Pages | 不启用，文档随源码维护                   |
| 合并方式                              | 仅 Squash；PR 标题与正文作为合并提交说明 |
| 分支管理                              | 合并后自动删除来源分支，允许更新落后分支 |
| 自动合并                              | 关闭，由维护者确认后合并                 |

`main` 必须通过 PR 更新，且管理员也遵守保护规则：要求 GitHub Actions 的 `Windows x64` 和 `Linux x64 / Ubuntu 22.04` 检查通过，分支保持最新，讨论已解决，并保持线性历史。禁止强制推送与删除主分支。

项目目前由单维护者管理，因此不要求第二人的审批或最后一次推送的他人批准；CI 门禁仍然生效。维护任务使用短期分支（自动化维护默认 `codex/` 前缀），不通过临时关闭保护来合并。

以 `V` 或 `v` 开头的版本标签禁止更新和删除，没有绕过名单；新版本使用新标签。标签发布流程见 [版本与发布](releasing.md)。

## Actions 与安全

- 保留 Actions，只允许当前工作流使用的官方 Action 精确提交 SHA，并要求 SHA 固定。调整 Action 版本时，同时更新工作流和仓库白名单。
- 工作流默认只有仓库读取权限，不能自动批准 PR；只有标签发布任务获得 `contents: write`，用于上传 Release。
- 所有外部 Fork PR 的工作流都需维护者批准后运行；不为这些 PR 开放写入权限或仓库 Secrets。
- 开启 Dependabot 漏洞提醒与安全更新 PR；没有配置常规版本更新计划，不自动合并安全更新。
- 开启 Secret scanning 和推送保护；开启私密漏洞报告，入口见 [安全政策](../SECURITY.md)。

`package.json` 的 `private: true` 继续保留，用于避免误发布到 npm，与 GitHub 仓库的公开状态无关。发布文件数量、命名和简体中文说明规范保持不变。
