# 原型验证记录

日期：2026-10-30；Windows x64；Rust 1.99.1 / Node 24.14.1。

## 自动化

- TypeScript 严格类型检查、Vite 生产构建。
- Rust：来源网段边界、配置原子保存和损坏检测、设备解析及精确成员过滤。
- 网关集成：跨组隔离、服务器操作拒绝、选定 transport 后的 host 命令拒绝、transport-id 越权拒绝。
- 网关集成：并发二进制流、停止组立即关闭会话并释放端口、停止一组不影响另一组和本地上游。
- 网关集成：USB/local 选择语义、tracking 中设备消失、订阅客户端断开后的会话清理、占用端口启动失败。
- 网关集成：绑定真实本机网卡 IP，分别验证不匹配来源被关闭、匹配来源能够查询设备；此项仍为同机连接。
- 系统 adb + 原型 EXE + 隔离虚拟上游：devices、get-state、现代 tport shell v2、transport-id、二进制 push/pull 一致性。

结果：19 项 Rust 测试通过；Clippy 全目标 `-D warnings` 通过；交付副本标准 adb 集成测试通过；npm 官方源 audit 为 0。

其中 9 项规则生命周期测试使用可注入的模拟防火墙后端：验证删除前先停止监听、清理失败保留组、批量退出清理、遗留规则恢复、重启后重试、无规则跳过提权、核查规则是否确实消失，以及清理一组不影响其它组。未通过这些测试修改实际 Windows 防火墙。

这些测试没有连接真实 Android 设备。虚拟上游只实现测试所需协议，不能替代真机兼容性验证。

## 实际 Tauri 窗口

原生 Computer Use 截图两次超时，随后使用本应用 WebView2 的临时本机 CDP 端口进行 Playwright 回归。测试结束后关闭测试应用，正常启动的交付 EXE 不开启该调试端口。

- 刷新不覆盖草稿中的名称、设备勾选；暂未连接设备保留勾选。
- 保存结果与 JSON 文件一致。
- 启动共享后禁止编辑，复制命令成功。
- 建立真实 TCP 长连接后界面显示对应设备；停止共享关闭连接并恢复编辑。
- 空状态、新建、运行中直接删除组，以及非法来源地址的错误反馈。
- 只保留侧栏一个新建入口，删除“工作空间”；无组首页保留简洁图标、说明和三步流程，不重复放置新建按钮。
- 清理记录损坏时，删除会停止共享并保留组；修复后可重试删除，成功后无横幅。
- 删除多组中的一组后，自动显示剩余组；最后一个组删除后显示简洁欢迎首页。
- 本机设置窗口展示正确的上游端口。
- 本机设备列表入口显示实际数量；虚拟上游减少 / 恢复设备时，入口数字和列表同步更新。
- 中英文切换覆盖标题、状态、设置、占位文字和错误反馈，并保留草稿；语言和主题偏好在刷新后保留。
- 浅色 / 深色主题切换正常，已检查两套配色；移除旧的双句侧栏提示，底部三个方形图标入口可用。
- 关于页展示构建注入的时间、实际版本、作者、GPLv3；项目许可证和第三方组件许可证均从 EXE 内置内容读取，第三方声明按组件加载以避免整页大文本阻塞。
- 通过原生 WM_CLOSE 关闭主窗口；规则清理失败时窗口保留并显示原因，修复后重试成功，监听端口释放、程序退出。

## 用于后续讨论的流程

1. 第一次运行能否清楚区分“没有启动 ADB Server”和“ADB 已连接但没有设备”？
2. 设备列表是否需要与组配置分成独立页面？
3. 选网卡后默认允许其子网，还是默认要求填写具体主机？
4. 显式保存、启动、配置防火墙的顺序是否自然？
5. 右侧命令能否让远端使用者直接完成操作？
6. 关闭窗口停止共享是否符合习惯，是否需要托盘？

目前的呈现只是可运行的讨论样本，这些行为可在后续迭代调整。
